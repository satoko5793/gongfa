# 第一期：价格系统重构实施计划

## 范围

第一期只做价格系统，不扩散到订单、导入、商城渲染、小程序归档等其他主题。

本期范围固定为：

- 后端定价规则核心
- 重算触发链路
- 配置更新后的同步重算联动
- `pricing_meta` 解释结构
- 后台最小价格解释展示

## 目标

本期目标不是改价格口径，而是把价格系统变成“更稳定、更好解释、更好继续拆”的状态。

最低目标：

- 给 `backend/src/domain/pricing/` 建立稳定骨架
- `backend/src/services/pricing.js` 保留兼容入口，但开始转发部分职责
- 配置保存后同步重算变成明确行为
- `pricing_meta` 能解释关键命中规则
- 后台商品详情能看出定价主导原因

## 目标结构

第一期目标目录：

- `backend/src/domain/pricing/`
- `backend/src/domain/pricing/core/`
- `backend/src/domain/pricing/rules/`
- `backend/src/domain/pricing/explain/`

第一期建议落下的职责：

- `core/reprice-products.js`
  负责同步重算摘要和重算状态收口。
- `core/reference-caps.js`
  负责满攻、满血、词条参考区间、双满判定、基础价格映射工具。
- `rules/discounts.js`
  负责老卡折扣、双词条涨幅等折扣与增益规则。
- `explain/pricing-meta.js`
  负责统一组装 `pricing_meta` 解释结构。

## 迁移顺序

1. 先补两份文档并更新索引。
2. 新建 `backend/src/domain/pricing/` 骨架。
3. 把 `pricing.js` 中纯工具和解释逻辑开始抽出。
4. 保留 `backend/src/services/pricing.js` 兼容导出，不大改调用方。
5. 收口配置保存后的同步重算结果。
6. 给后台单卡价格说明补关键解释字段。
7. 做本地验证。
8. 只发测试服验证。

## 配置与重算联动要求

第一期必须保证下面这件事是确定的：

- 后台保存 `pricing_controls` 后，必须同步触发一次商品重算。

重算成功后，至少要保证：

- `price_quota` 写回
- `pricing_meta` 写回
- 响应里能区分：
  - 配置已保存
  - 重算成功
  - 重算失败

本期不做异步任务队列，继续保持同步重算。

## `pricing_meta` 最小解释模型

第一期至少让 `pricing_meta` 能稳定表达下面这些信息：

- 档位
- 是否严格双满
- 属性价
- 词条价
- 双满参考价是否命中
- 词条是否被无词条基线保底抬起
- 老卡折扣是否命中
- 双词条涨幅是否命中
- 金卡专属规则是否命中
- 最终价由哪一层主导

## 后台最小展示要求

第一期不重写后台定价页面结构，但商品详情里的价格说明至少要补出：

- 当前档位
- 严格双满与否
- Atlas / Wear / Final 三层价格
- 双满保底是否命中
- 词条不低于无词条是否命中
- 老卡折扣是否命中
- 双词条涨幅是否命中
- 最终主导原因

## 成功标准

达到下面条件，本期才算完成：

- 紫卡严格双满会命中 `atlas_double_full_quota`
- 红卡严格双满会命中 `atlas_double_full_quota`
- 同档位同数值下，带词条最终价不低于无词条
- 金卡无词条专用体系仍独立生效
- 金卡攻击乘区仍只对带词条金卡生效
- 配置保存后现货一定完成同步重算
- 后台能从 `pricing_meta` 看出关键命中规则
- 测试服验证通过

## 本地测试清单

- `node --check` 通过改动的后端与前端文件
- `python3 scripts/validate_frontend.py --base-url http://127.0.0.1:8090`
- 用脚本或 `node -e` 复核这些场景：
  - 紫卡严格双满命中双满参考价
  - 红卡严格双满命中双满参考价
  - 同数值无词条 / 单词条 / 双词条不倒挂
  - 老卡折扣跳过珍卡与双满
  - 金卡无词条专用体系不受词条攻击乘区污染

## 测试服验证清单

按下面顺序固定执行：

1. 打开测试服后台。
2. 修改一个明确可识别的双满参考价。
3. 保存配置。
4. 检查对应档位严格双满商品价格是否同步变化。
5. 打开商品详情，确认价格解释字段正常。
6. 抽一组无词条 / 单词条 / 双词条样本，确认没有倒挂。
7. 冒烟验证商城、个人后台、配置保存和下单主链路。

## 回滚方式

如果第一期改动在测试服验证不通过，回滚方式固定为：

1. 保持正式服不动。
2. 测试服重新部署到上一个稳定版本。
3. 保留文档和子目录骨架。
4. 回退本期解释增强和同步重算状态增强代码。

## 本期不通过条件

出现以下任一情况，即视为本期未完成：

- 配置保存后商品不重算
- 严格双满仍不吃双满参考价
- 词条卡仍可能低于无词条
- `pricing_meta` 仍解释不清
- 后台保存配置导致其他按钮交互失效
